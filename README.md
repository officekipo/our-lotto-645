- API 데이터 처리 로직 자체는 변경하지 않았습니다.

### PHASE 13-4 — Web QR 카메라 권한 흐름 개선
- Web에서 권한 확인용 `getUserMedia()`를 중복 호출하지 않고 `CameraView`가 실제 카메라 요청을 담당하도록 수정했습니다.
- 권한 요청 실패 때문에 `CameraView`가 마운트되지 않아 브라우저의 실제 카메라 오류를 확인하기 어려웠던 흐름을 개선했습니다.
- Web 카메라가 `HTTPS` 또는 `localhost` 같은 보안 컨텍스트에서 실행되는지 확인하고, 조건을 만족하지 않으면 구체적인 안내를 표시합니다.
- QR 스캐너 재시도 시 `CameraView`를 다시 마운트하도록 처리했습니다.
- Native의 `expo-camera` 권한 요청 흐름은 유지했습니다.

## PHASE 14 — GitHub + Vercel Web 배포 준비

기준일: 2026-09-19

- GitHub 저장소에 올릴 수 있도록 `.gitignore`를 추가했습니다.
- Vercel에서 Expo Web 정적 번들을 자동 생성할 수 있도록 `vercel.json`을 추가했습니다.
- `npm run build:web` 스크립트를 추가했습니다.
- 현재 `expo.web.output: "single"` 구조는 유지했습니다. 이 프로젝트는 Expo Router 기반 라우팅이 아니라 `App.tsx` 단일 진입 구조이므로 기존 Web 동작을 불필요하게 변경하지 않았습니다.
- Vercel 배포 시 `npm run build:web` → `dist`를 배포하도록 구성했습니다.
- 배포 후 HTTPS 환경에서 모바일 Web 카메라/QR 스캔을 실제 기기로 확인할 수 있습니다.
- GitHub/Vercel 계정 연결과 실제 배포 실행은 사용자 계정에서 진행해야 합니다.

### 권장 배포 순서

1. 프로젝트 전체를 GitHub 저장소에 업로드
2. Vercel에서 해당 GitHub 저장소 Import
3. Build Command: `npm run build:web`
4. Output Directory: `dist`
5. Deploy
6. 발급된 HTTPS 주소를 휴대폰에서 접속
7. `당첨 확인 → QR로 번호 불러오기` 테스트

### 공식 문서 참고

- Expo Web export: `npx expo export --platform web`
- Vercel 정적 배포 설정은 Expo 공식 Web 배포 문서 기준으로 구성했습니다.
